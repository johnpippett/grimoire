# 21.04 MCP and PyJWT Security Refresh

## 2026-11-20

Updated the lock with `uv lock --upgrade-package mcp --upgrade-package pyjwt`.
MCP moves from 1.29.0 to 1.30.0; PyJWT moves from 2.13.0 to 2.15.1.
The MCP `<2` bound stays in place. No other package changes. Uv updates the
lock format revision from 3 to 5.

These versions address the audit findings for these packages. A frozen export
checked with `uvx pip-audit --disable-pip --no-deps -r /dev/stdin --format json`
reports no advisories for either package, including the previously unpatched
PyJWT finding. Other locked packages still have 132 reported findings.

Verification from `grimoire-mcp/`:
`uv run --frozen --with pytest python -W default -m pytest tests ../tests -q`
reported `62 passed, 1 warning, 50 subtests passed in 5.60s` on Python 3.15.2.
The warning comes from AnyIO's pytest plugin, not project code.

The [PyJWT changelog](https://github.com/jpadilla/pyjwt/blob/master/CHANGELOG.rst)
describes stricter key validation, rejected JWKS redirects, and changes to
JWKS caching and exception handling. Version 2.15.1 restores padded JWS input.
MCP release-note retrieval was blocked by GitHub API rate limits; its full
release notes were not verified during this change.

Rollback: revert this branch's commit and run `uv sync --frozen` in
`grimoire-mcp/`. This restores vulnerable versions. No service restart or
deployment is part of this change.

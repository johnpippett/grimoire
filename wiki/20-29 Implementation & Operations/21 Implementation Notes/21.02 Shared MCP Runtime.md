# 21.02 Shared MCP Runtime

## 2026-09-25 — One local server for multiple agents

The previous efficiency change cached retrievers within each process.
Codex still started one stdio server per MCP client.
The running desktop accumulated 74 Grimoire stdio servers.
Their combined logical swap use was 6,357 MiB immediately before cleanup.

`grimoire-mcp serve-http` now provides an authenticated Streamable HTTP endpoint.
It binds only to `127.0.0.1` and uses one Python process with four worker threads.
All HTTP clients use the same registry, index cache, and tools.
Stateless HTTP requests do not retain MCP sessions after client disconnects.
The existing stdio command, index format, and refresh timer remain available.
Stdio clients still start separate processes.

The local `grimoire-mcp.service` is enabled under the user systemd manager.
It serves `http://127.0.0.1:8767/mcp` with a private token from `~/.wiki-rag/mcp-token`.
Codex now uses this URL and the matching authorization header in its private configuration.
Unrelated Codex settings were preserved.
The private backup is `~/.codex/config.toml.pre-grimoire-shared-20260925-104111`.

After successful HTTP calls, the 74 exact legacy processes received `SIGTERM`.
The cleanup matched their command, parent, and start time before sending each signal through a process file descriptor.
One shared server remained, with 121 MiB PSS and no swap.
After indexing the updated wiki, this process used 161 MiB PSS and still had no swap.
PSS measures proportional resident RAM. Logical swap does not equal physical zram allocation.
Existing desktop task connections need a Codex restart to use the new registration.
The desktop application was not restarted during this work.

## Verification

- The startup regression failed before implementation and passed after implementation.
- All 34 existing tests passed.
- The real-MCP test passed with 12 concurrent clients, one unchanged server PID, and no child processes.
- Authentication, Host and Origin checks, occupied-port rejection, private token permissions, and index persistence passed.
- HTTP and stdio clients found all 11 indexed projects and successfully queried the Grimoire wiki.
- The installed Codex CLI accepted the HTTP registration. The refresh timer remained enabled.

Run the test and use the setup instructions in `docs/grimoire-shared-runtime.md`.
Evidence is in `grimoire-mcp/benchmarks/results/2026-09-25-shared-runtime.json`.
Simultaneous client and service startup at login was not tested.
Use an authenticated MCP call to confirm readiness; systemd can report active before the port opens.

## Rollback

Restore the Grimoire registration from the private Codex backup.
Preserve any unrelated configuration changes made after this backup.
Restart Codex, then stop and disable `grimoire-mcp.service`.
No wiki or index restoration is necessary.
The old registration permits separate server processes again.

This resource fix is complete in the source and local service configuration.
The broader modernization specification remains proposed and awaits approval.

# 21.03 Grimoire Modernization

## 2026-09-25 — Portable project knowledge and bounded search

Grimoire keeps the project wiki as its source of durable knowledge. Fresh agents
read `wiki/README.md` and topic notes before project work. Continuing agents
repeat that step after a topic change or context loss. Coordinators give
workers selected context and own the final wiki note and session-log link.
Agents use file tools when MCP search is unavailable. Search results refer to
registered index generations; agents read the active checkout for current
checkout facts.

The project `AGENTS.md`, both Grimoire skills, the wiki template, and setup
guides now use this contract. This project's wiki entry point lists its scope,
terms, current work, limits, and topic notes. Its orientation has 250 words
before the numbering reference.

`query_wiki` now omits zero-score hits and accepts `top_k` values from 1 to 25.
Each result gives bounded excerpts, source paths, indexed roots, index time,
generation, and chunk ID. The response reports omitted hits and truncation
within 8,000 characters. `read_wiki_passage` returns the indexed chunk in
pages. It uses generation and chunk ID, and it rejects unknown or stale
references. The index format and local BM25 search remain in use.

`setup-projects.py --upgrade` previews exact recognized Grimoire contracts.
`--apply` saves the original `AGENTS.md` bytes in a restricted backup before
it changes the file. It keeps custom instructions and skips ambiguous edits.
Scheduled index refreshes do not request upgrades. New wiki entry points use
the supplied project scope when setup creates them.

## Why

The short entry point gives new agents project context without a full scan of
old notes. The coordinator keeps one authoritative wiki update after worker
handoffs. Bounded search results prevent large tool replies. Passage pages
let agents recover complete evidence before they use a search excerpt.

## 2026-09-25 — Review corrections

The agent contract now requires a full initial wiki read for an agent that
works alone and for a coordinator. A delegated worker can use sufficient wiki
context and source paths from the coordinator. It reads more notes when needed.
After a topic change or context loss, the coordinator gives the worker new
context. The coordinator owns final wiki edits unless it assigns a note to a
worker. The root contract, skills, wiki template, setup guide, and generated
contract now state these roles.

The `--upgrade` preview now prints a before/after diff of changed lines.
It does not show adjacent local rules or write a file or backup.
Exact fingerprints recognize earlier stock workflow text,
including the previous generated gate and the pre-correction root contract.
Edited workflow sections remain skipped. Apply still saves the original bytes
for rollback and keeps unrelated instructions.

The validation report now shows token use for each continued trial turn.
The old turn used 24,605 input, 22,272 cached input, and 415 output tokens.
The new turn used 21,726 input, 19,200 cached input, and 478 output tokens.
The resumed CLI totals included both turns. The report subtracts the initial
turn to obtain each continued turn's use. The initial-turn comparison still
comes from one trial and does not measure these later contract edits.

These corrections make worker intake clear, show exact proposed contract
changes before apply, and keep the trial measurements accurate. The preview
E2E record is at `/tmp/grimoire-upgrade-preview-e2e-final.json` on the test host.
It confirms both diffs, unchanged files, absent backups, and a rerun command.
The combined suite passed 62 tests and 50 subtests. The setup and contract
guidance suite passed 30 tests. The earlier six-step search and ten-step shared
HTTP E2E results remain valid because their source did not change.
Restore the previous contract and setup script from this worktree's saved
baseline if rollback is necessary. No installed service change is part of
these corrections.

installation was synchronized, and the existing shared service was restarted.
The HTTP registration, credentials, timer schedule, and index format remain
unchanged. The service advertises all four tools, including passage retrieval.

worktree received the same instruction update. The migration preserved custom

updated separately and checked against saved originals. A later automatic
preview can still skip customized sections; this does not mean they are old.

reported zero additional files in each direct-child project.

# 11.01 Retire grimoire-mcp for a Shared Memory Repo

## 2026-11-18 — Decision

The user stopped the `grimoire-mcp` search service and its refresh timer on
the always-on host. A local git repository at `~/memory` on that host now holds
the user's shared agent memory. Claude Code and OpenCode load its `ME.md` file
at session start. Agents use `rg` to search its `topics/` files. A `remember`
skill writes new facts into the repository and commits them.

## Why

- Research (2026-11-18) found that FOSS memory frameworks (Mem0, Letta,
  Graphiti, Cognee, and others) store LLM-extracted facts in databases. A
  person cannot review or diff these facts in git.
- Most of the user's agent work is local, non-project work. Coding projects
  run in cloud agents, and cloud agents cannot reach a service that listens
  only on the loopback interface.
- Agent knowledge was split across seven locations. One repository and one
  write path stop agents from asking the user the same questions again.
- arXiv 2602.11988 (2026) reports that long context files increase cost and
  do not generally improve task success. The new global instruction files are
  shorter.

## What changed on the host

- `grimoire-mcp.service` and `grimoire-wiki-rag-refresh.timer` are stopped
  and disabled. The OpenCode registration for the service was removed.
- The Claude Code registration is in the protected `~/.claude.json` file. The
  user must remove it with `claude mcp remove grimoire -s user`.
- The project wikis remain in place. Agents read them with file tools.
- The source code in this repository did not change.

## Verify

```bash
systemctl --user is-active grimoire-mcp.service grimoire-wiki-rag-refresh.timer  # inactive
git -C ~/memory log --oneline
```

## Rollback

```bash
systemctl --user enable --now grimoire-mcp.service grimoire-wiki-rag-refresh.timer
```

Restore the earlier OpenCode configuration from
`~/Backups/memory-consolidation-2026-11-18/opencode.json`.
